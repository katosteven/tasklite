About Tasksite

A minimal, security-first task & project manager for small teams — designed as a clean reference implementation of a modern Django 5 application.

What is Tasksite? and Where this started

Tasksite is a lightweight collaboration tool that helps small teams plan projects, break them down into tasks, and capture context as the work progresses.

This project began with django.nV - a deliberately vulnerable Django web application created by NetSPI as a security training tool. It ships with real-world vulnerabilities baked in: OS command injection via file uploads, raw SQL queries open to injection, missing CSRF tokens, absent HTTP security headers, hardcoded secrets, and more.
As part of an MCS 7201 Computer Systems Security assessment, django.nV was scanned with Bandit (static analysis) and OWASP ZAP (dynamic analysis), revealing 20 issues across all severity levels. Tasksite is the result: a complete, secure rewrite of the same application, addressing every finding and applying secure-by-default Django practices throughout.

What you can do

  • Manage projects. Create projects with a description, priority and optional due date. Add teammates as members.
  • Track tasks. Add tasks under any project, assign them to members, mark them complete, and see progress roll up to the project.
  • Capture decisions. Post titled notes on any task to keep a clear history of why work happened.
  • Share files safely. Upload attachments to a project; downloads are streamed only to authorised members.
  • Find anything fast. Search projects and tasks, scoped to what your account can see.
  • Personal dashboard. See your most recent projects and your own open tasks at a glance.
  • Account self-service. Register, log in, change your password, reset by email and edit your profile (bio + avatar).

Built with security first

  • Django 5 with the latest security patches; secrets driven by .env — never committed.
  • PBKDF2 password hashing and Django's full password-validator stack (min length 10, no common passwords, etc.).
  • CSRF protection on every form; sessions and CSRF cookies are HttpOnly + SameSite=Strict + Secure in production.
  • Strict Content-Security-Policy with no unsafe-inline — every directive is set explicitly.
  • HSTS, X-Frame-Options: DENY, X-Content-Type-Options: nosniff, same-origin referrer policy.
  • Per-object access control: every queryset is scoped to owner OR member; deletes are owner-only.
  • Uploads go through Django's file storage layer with a 5 MB cap; downloads are gated by membership.
  • Static assets served via WhiteNoise so security headers apply to every response.
